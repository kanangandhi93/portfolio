Missing Server-Side Enforcement of Terms Acceptance

Scope: POST /api/users/register/ (has_accepted_terms_and_condition)
Status: Remediated & Verified

// 01. EXECUTIVE SUMMARY

During security and QA auditing of the user onboarding service, a business logic validation flaw was identified on the registration endpoint. The application relies primarily on front-end controls to enforce user consent. By intercepting and altering the registration payload to explicitly set `has_accepted_terms_and_condition: false`, the server-side API still accepts the registration, provisions the account, and issues authentication tokens.

// 02. PROOF OF CONCEPT & REPRODUCTION FLOW

### 1. Intercept Registration Request Populate signup form and capture outbound request before transmission using an intercepting proxy. ### 2. Alter Consent Parameter Modify the JSON payload parameter `"has_accepted_terms_and_condition"` from `true` to `false`: ```http POST /api/users/register/ HTTP/2 Host: app.[redacted-edtech].com Content-Type: application/json { "email": "audit_user@example.com", "password": "[REDACTED_PASSWORD]", "firstName": "Test", "lastName": "User", "preferred_language": "en", "remember": false, "has_accepted_terms_and_condition": false } ``` ### 3. Observed Response The server responds with `HTTP 201 Created` and issues production tokens despite user explicitly declining terms: ```http HTTP/2 201 Created Content-Type: application/json { "access_token": "eyJhbGciOiJIUzI1[REDACTED]...", "refresh_token": "eyJhbGciOiJIUzI1[REDACTED]...", "user": { "id": 182895, "email": "audit_user@example.com", "full_name": "Test User", "access_role": "student", "has_accepted_terms_and_condition": false, "terms_accepted_at": null } } ```

// 03. BUSINESS IMPACT & REGULATORY EXPOSURE

Regulatory and legal exposure under GDPR/CCPA for processing user data without verifiable consent; undermines contractual enforceability of terms of service and liability limitations.

// 04. REMEDIATION & QA ENGINEERING GUIDANCE

### Node.js / Express Example Fix ```javascript // Middleware / Route Validator if (req.body.has_accepted_terms_and_condition !== true) { return res.status(400).json({ error_code: "TERMS_NOT_ACCEPTED", detail: "You must accept the Terms and Conditions to create an account." }); } ``` ### Python / Django REST Framework Example Fix ```python from rest_framework import serializers class UserRegistrationSerializer(serializers.ModelSerializer): has_accepted_terms_and_condition = serializers.BooleanField(required=True) def validate_has_accepted_terms_and_condition(self, value): if value is not True: raise serializers.ValidationError("Acceptance of Terms and Conditions is required.") return value ```
