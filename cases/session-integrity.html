HIGH (CVSS 8.0) Session Management & Integrity QA Target: Healthcare & Genetic Analytics Platform

Session Replay & Dynamic Account Switching via Session Overwrite

Scope: GET /user/ (Cookie: sessionid)
Status: Remediated & Verified

// 01. EXECUTIVE SUMMARY

The web application relied exclusively on a `sessionid` cookie without binding sessions to client IP, TLS context, or device fingerprint. Supplying a different user’s session identifier caused the backend to respond with Set-Cookie headers that overwrote active browser sessions, allowing seamless dynamic account takeover.

// 02. PROOF OF CONCEPT & REPRODUCTION FLOW

### 1. Session Replay 1. Captured session cookie from User A session. 2. Injected session cookie into independent clean browser session; observed immediate access to User A health profile without challenge. ### 2. Dynamic Session Overwrite 1. Intercepted outbound GET /user/ from User B and replaced cookie with User A's session. 2. Server accepted modified cookie and returned headers instructing the browser to overwrite its session, immediately switching active user context to User A.

// 03. BUSINESS IMPACT & REGULATORY EXPOSURE

Direct account takeover and dynamic session hijacking without session fixation protection or anomaly detection.

// 04. REMEDIATION & QA ENGINEERING GUIDANCE

1. **Context Binding:** Bind session tokens to client TLS context or device fingerprinting. 2. **Session ID Regeneration:** Always regenerate session identifiers upon authentication and state changes. 3. **Reject Arbitrary Session Overwrite:** Enforce server-side session integrity validation to ensure sessions cannot be dynamically reassigned via modified client headers.
