Auditor: Kanan Gandhi
P4 / MEDIUM (CVSS 6.5) Authentication & Transport Security Target: National Telecommunications & Mobile Carrier

Cleartext Credential Transmission via Hardcoded HTTP Form Action

Scope: https://www.[redacted-telecom].com.au/signon/portal/login.fcc
Classification: VRT: Broken Authentication > Weak Login Function > Over HTTP

// 1. Executive Summary

During an authentication security assessment of customer-facing single sign-on (SSO) portals, a transport security flaw was identified on the primary enterprise login interface. While the initial webpage was served securely over HTTPS, the underlying HTML form was hardcoded with an unencrypted http:// form action targeting the CA SiteMinder authentication handler.

Submitting the form causes user credentials (USER and PASSWORD) to be transmitted across the local network and public internet in unencrypted plaintext over port 80. While the edge CDN issues an HTTP 302 redirect to HTTPS upon receipt, the sensitive credentials have already crossed the wire in cleartext, exposing customers to passive eavesdropping and Man-in-the-Middle (MITM) credential harvesting.

// 2. Vulnerable Form Action & Code Evidence

Direct source inspection of the authentication page at /signon/portal/login.fcc confirmed the insecure form configuration: 

<FORM NAME="Login" ACTION="http://www.[redacted-telecom].com.au/siteminderagent/portal/login.fcc" METHOD="POST">
    <INPUT TYPE=HIDDEN NAME="SMENC" VALUE="ISO-8859-1">
    <INPUT type=HIDDEN name="SMLOCALE" value="US-EN">
    <input type=hidden name=target value="">
    <input type=hidden name=smauthreason value="">
    <input type=hidden name=smagentname value="">
    <input type=hidden name=postpreservationdata value="">
    <input id="USER" NAME="USER" SIZE="25">
    <input type="password" id="PASSWORD" NAME="PASSWORD" SIZE="25">
</FORM>

// Plaintext Transmission Interception

Sending a POST request to the cleartext HTTP endpoint demonstrates that the edge receives the credentials prior to issuing a redirect: 

POST http://www.[redacted-telecom].com.au/siteminderagent/portal/login.fcc HTTP/1.1
Host: www.[redacted-telecom].com.au
Content-Type: application/x-www-form-urlencoded

USER=customer_account&PASSWORD=CleartextPassword123!&SMENC=ISO-8859-1&target=

→ HTTP/1.1 302 Moved Temporarily
Server: AkamaiGHost
Location: https://www.[redacted-telecom].com.au/siteminderagent/portal/login.fcc

// 3. Additional SSO Reconnaissance & Logic Weaknesses

1. Proprietary SSO Topology Exposure

The login flow query parameters and hidden form values leak internal CA SiteMinder deployment metadata:

  • REALMOID: 06-dd57b946-1753-43da-[REDACTED] (Internal realm database UUID)
  • SMAGENTNAME: -SM-7LF8ifsjXF2F6vC8[REDACTED] (Encrypted web agent name)
  • TYPE: 33554433 (Form-based authentication mechanism)

2. Absence of Anti-CSRF Token

The login form completely lacks cryptographic CSRF tokens, exposing users to login CSRF attacks where an attacker forces a victim's browser to authenticate into an attacker-controlled account context.

3. Client-Side Only Rate Limiting Bypass

Authentication attempts were tracked purely via client-side cookie logic (SMTRYNO). Because no server-side IP or account-level throttling was enforced, an attacker can automate unrestricted credential stuffing by omitting or clearing cookies between requests.

// 4. Threat & Business Impact

Credential Sniffing (MITM)

Adversaries on public networks (coffee shops, hotels, public Wi-Fi) can capture plaintext credentials in real-time using passive packet analysis.

SSO Perimeter Compromise

Compromised SiteMinder credentials provide lateral access across all federated customer accounts, billing data, and carrier services.

// 5. Security Remediation Plan

  • 1. Enforce HTTPS Action URL: Update the login template to strictly target https://www.[redacted-telecom].com.au/....
  • 2. HSTS with Preload: Deploy Strict-Transport-Security: max-age=31536000; includeSubDomains; preload to force browsers to automatically upgrade insecure form submissions.
  • 3. Content Security Policy: Enforce form-action 'self' https://* to block unencrypted form actions at the browser engine level.
  • 4. Server-Side Rate Limiting & Anti-CSRF: Enforce server-side account lockouts / CAPTCHA on failed attempts and inject unique cryptographic CSRF tokens on all login forms.
